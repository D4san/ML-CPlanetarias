skills/mlcp-quality-review/; skills/develop-mlcp-web/ referencias si corresponde; scripts/check-skill-mirrors.mjs y pruebas; espejos .agents/skills y .codex/skills de las skills aprobadas; README de skills.

Las rutas son relativas a la raíz del repositorio. Los nombres nuevos son destinos propuestos que A02 fija antes de implementarlos. Pedir al integrador una reasignación si aparece una necesidad fuera de esta lista; continuar con lo independiente.

## Lista de tareas

- [ ] Crear skill de revisión con entradas, pruebas, matriz Rxx/ACxx, evidencia y estados. Diferenciar código correcto, contenido sustentado, diseño legible y autorización editorial.
- [ ] Preparar casos de aceptación/rechazo: una tarea con tests aprobados pero fuente ausente, otra con buen contenido y fallo reproducible móvil, y una entrega completa.
- [ ] Generalizar el validador de espejos mediante un inventario explícito o descubrimiento acotado de las skills del repo. Verificar SKILL.md y todos los recursos distribuidos, incluido agents/openai.yaml si existe.
- [ ] Sincronizar desde skills/ hacia los espejos con comparación de contenido. Conservar la skill web existente como implementación; no crear una segunda skill web redundante.
- [ ] Documentar qué skill usa cada tipo de tarea. Las skills orientan el trabajo; el usuario/integrador decide asignaciones, concurrencia y publicación.

## Criterios de aceptación

- [ ] D04-AC1: Las cuatro nuevas skills tienen triggers, entradas, pasos, outputs y condición de cierre verificables.
- [ ] D04-AC2: El validador detecta espejo faltante, divergencia y recurso auxiliar desactualizado; no se limita a una skill fija.
- [ ] D04-AC3: Los espejos son idénticos a la fuente canónica y validate:skills pasa.
- [ ] D04-AC4: Los ensayos de revisión rechazan evidencia faltante aunque el agente diga terminado.

## Evidencia y validación

Pruebas del validador y npm run validate:skills; matriz de ensayos de la skill de QA y documentación de uso.

Aplicar los gates proporcionales de VALIDATION.md. Completar [el informe de entrega](../templates/DELIVERY.md); marcar un criterio solo con evidencia. El agente propone entrega; el revisor acepta la tarea en BOARD.md.

## Criterio de logro

Las skills quedan disponibles, coherentes y utilizables por agentes con contexto limitado.

## Límites de esta tarea

No editar archivos protegidos mediante una vía alternativa si el entorno deniega escritura; entregar fuentes canónicas y registrar el bloqueo del espejo. No instalar plugins ajenos al alcance.
