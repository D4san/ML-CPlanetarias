config/course.config.ts; src/lib/course-config.ts y tests; ADR-0002; src/lib/course-content.ts.

## Archivos permitidos y entrega

config/course.config.ts; src/lib/course-config.ts y tests; docs/guides/FORK_CONFIGURATION.md; consumidores mínimos asignados por el integrador.

Las rutas son relativas a la raíz del repositorio. Los nombres nuevos son destinos propuestos que A02 fija antes de implementarlos. Pedir al integrador una reasignación si aparece una necesidad fuera de esta lista; continuar con lo independiente.

## Lista de tareas

- [ ] Implementar defaults del curso y overrides por sesión únicamente para los campos acordados. La precedencia será valor de sesión definido → valor del curso → default documentado; false no puede desaparecer por usar ||.
- [ ] Migrar la sección s01 a sessions.S01 según ADR, actualizando todos los consumidores en la misma entrega. El fork actual debe producir el mismo comportamiento tras la migración.
- [ ] Implementar identidad del sitio y enabledSessionIds ordenados. Validar duplicados, IDs desconocidos y overrides para sesiones inexistentes. Las sesiones sin rutas no requieren defaultRouteId.
- [ ] Resolver rutas a partir de disponibilidad de la sesión. Definir si se heredan todas al omitir enabledRouteIds; rechazar lista vacía para una sesión que necesita ruta y default deshabilitado.
- [ ] Probar combinaciones de directo/interactivo, docente true/false y vista inicial. La URL puede seleccionar un estado permitido pero no habilitar sesiones/rutas prohibidas. Actualizar ejemplos de configuración con campos que realmente funcionen.

## Criterios de aceptación

- [ ] B03-AC1: Se prueba explícitamente que un override false prevalece sobre true global.
- [ ] B03-AC2: S00 sin rutas es válida y S01 sin rutas habilitadas produce un error accionable.
- [ ] B03-AC3: El perfil anterior del piloto conserva sus tres rutas, modo interactivo y docente desactivado.
- [ ] B03-AC4: La identidad configurada llega a cabecera, pie y metadatos cuando se conecta en B04; no quedan opciones documentadas sin consumidor.

## Evidencia y validación

Tests de resolución con tabla entrada/salida, check y builds; ejemplo docente directo de una sola ruta.

Aplicar los gates proporcionales de VALIDATION.md. Completar [el informe de entrega](../templates/DELIVERY.md); marcar un criterio solo con evidencia. El agente propone entrega; el revisor acepta la tarea en BOARD.md.

## Criterio de logro

Un tutor configura el curso desde un archivo sin modificar JSX ni tener que entender la precedencia.

## Límites de esta tarea

No introducir preferencias persistentes, base de datos ni panel administrativo; no ocultar errores de configuración con defaults silenciosos.
