# G03 · Ensayar un fork limpio y cerrar su guía

Estado inicial: pendiente. Fase: 6 · S00 y forks. Responsable sugerido: Agente de reproducibilidad.

- Requisitos: R02,R03,R09,R12,R13.
- Dependencias aceptadas: G02, F04.
- Lectura común obligatoria: [README](../README.md), [contratos](../CONTRACTS.md) y [validación](../VALIDATION.md).

## Entradas

README, guía del fork, config, .nvmrc, package.json, .github/workflows/deploy-pages.yml, VALIDATION.md.

## Archivos permitidos y entrega

docs/guides/FORK_CONFIGURATION.md; README; contenido técnico S00 mediante integrador; evidence/G03.md; ejemplos de perfiles; workflow solo para correcciones portables justificadas y revisables.

Las rutas son relativas a la raíz del repositorio. Los nombres nuevos son destinos propuestos que A02 fija antes de implementarlos. Pedir al integrador una reasignación si aparece una necesidad fuera de esta lista; continuar con lo independiente.

## Lista de tareas

- [ ] Preparar una copia o checkout de ensayo con los cambios locales necesarios, en destino explícito y preservando el workspace. No crear ni publicar un remoto para simular un fork.
- [ ] Desde instalación limpia ejecutar npm ci, check, unitarias y build. Registrar SO, versiones y rutas de salida sin datos personales en docs publicables.
- [ ] Configurar identidad diferente, directo/docente, una sola ruta, solo S00 y ninguna sesión. Comprobar que la documentación permite hacerlo sin editar componentes.
- [ ] Probar raíz y una subruta distinta de la del autor; revisar enlaces, recursos, refresh y URLs excluidas. Revisar los valores fijos de BASE_PATH/SITE_URL y workflow Pages para explicar cómo adaptarlos.
- [ ] Registrar cada instrucción que falló, corregir guía/S00 y repetir únicamente los pasos afectados. Dejar una receta de publicación separada que requiere instrucción expresa y comprobación posterior.
- [ ] Restaurar perfiles de ensayo sin sobrescribir cambios ajenos; si se crearon servicios, cerrarlos únicamente cuando pertenezcan a esta tarea.

## Criterios de aceptación

- [ ] G03-AC1: Una instalación sin node_modules previo ejecuta el curso con requisitos documentados.
- [ ] G03-AC2: La identidad y selección se cambian desde configuración; rutas/recursos funcionan bajo una subruta ajena a /preview.
- [ ] G03-AC3: La guía distingue servir localmente, generar el build y publicar; no afirma que un push cualquiera es inocuo si main despliega.
- [ ] G03-AC4: El ensayo deja evidencia reproducible y no modifica el remoto ni publica un sitio.

## Evidencia y validación

Diario de ensayo con comandos/códigos de salida, perfiles exactos y resultados HTTP/UI; correcciones trazadas a guía/S00.

Aplicar los gates proporcionales de VALIDATION.md. Completar [el informe de entrega](../templates/DELIVERY.md); marcar un criterio solo con evidencia. El agente propone entrega; el revisor acepta la tarea en BOARD.md.

## Criterio de logro

Otro tutor puede reproducir la adaptación usando la guía, sin conocimiento implícito del autor.

## Límites de esta tarea

No instalar versiones distintas para ocultar incompatibilidades sin documentar; no afirmar que se probó un fork real remoto si solo fue ensayo local.
