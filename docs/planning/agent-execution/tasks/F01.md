- Dependencias aceptadas: E01, C01, D02.
- Lectura común obligatoria: [README](../README.md), [contratos](../CONTRACTS.md) y [validación](../VALIDATION.md).

## Entradas

Inventario E01; fichas C01; skill mlcp-example-research; fuentes bibliográficas S01; protocolos editoriales.

## Archivos permitidos y entrega

Fichas de preparación de ejemplos/conceptos en destinos A02; evidence/F01.md; actualización de columnas de fuentes en S01_UNIT_INVENTORY mediante integrador.

Las rutas son relativas a la raíz del repositorio. Los nombres nuevos son destinos propuestos que A02 fija antes de implementarlos. Pedir al integrador una reasignación si aparece una necesidad fuera de esta lista; continuar con lo independiente.

## Lista de tareas

- [ ] Tomar el inventario completo y formar una cola por unidades pendientes. Buscar un caso que ilustre la idea exacta, empezando por exoplanetas; ampliar a estrellas solo con justificación.
- [ ] Leer cada recurso elegido y registrar título, autores/institución, año, URL/DOI y ubicación que respalda la afirmación. Abrir y verificar enlaces; registrar fecha y acceso. Comprobar capítulos de bibliografía cuando se citan.
- [ ] Escribir una explicación propia breve y una definición sintética por concepto. Distinguir qué afirma la fuente y qué adapta el curso. No inventar métricas, tamaños de muestra, descubrimientos ni incertidumbres.
- [ ] Para cada ejemplo completar pregunta → representación → paradigma/tarea → modelo cuando aplique → baseline/evaluación → interpretación/límite. Un caso conceptual puede omitir ejecución, indicando su propósito.
- [ ] Relacionar cada unidad con al menos un ejemplo verificado; un ejemplo puede reutilizarse si ilustra realmente varias unidades. Entregar pedidos de figuras y sustituciones de casos genéricos o galácticos.
- [ ] Cuando una fuente sea inaccesible, intentar una fuente primaria alternativa o limitar la afirmación al contenido realmente consultado. Mantener la unidad pendiente si no se resuelve; continuar con las otras.

## Criterios de aceptación

- [ ] F01-AC1: El 100 % de unidades inventariadas tiene un ejemplo revisado o un bloqueo individual explícito; F01 se acepta completa solo sin lagunas requeridas.
- [ ] F01-AC2: Cada afirmación científica nueva tiene soporte localizado y cada definición distingue síntesis del curso de formulación de fuente.
- [ ] F01-AC3: Todos los casos cumplen exoplanetas → estrellas justificado; no hay ejemplos de galaxias.
- [ ] F01-AC4: Los recursos visuales solicitados tienen derechos conocidos o se proponen como gráficos/ilustraciones originales; enlazar no se confunde con permiso de copia.

## Evidencia y validación

Matriz unidad → ejemplo → afirmación → fuente/ubicación → límite → asset; revisión de fuentes y enlaces.

Aplicar los gates proporcionales de VALIDATION.md. Completar [el informe de entrega](../templates/DELIVERY.md); marcar un criterio solo con evidencia. El agente propone entrega; el revisor acepta la tarea en BOARD.md.

## Criterio de logro

La integración de contenido puede realizarse sin pedir al desarrollador que invente ejemplos o justificaciones científicas.

## Límites de esta tarea
