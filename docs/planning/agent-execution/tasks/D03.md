- Dependencias aceptadas: A02, A03.

## Entradas

skill-creator; VISUAL_SYSTEM.md; contrato de asset; ejemplos existentes; skill imagegen disponible al ejecutar generación.

## Archivos permitidos y entrega

skills/mlcp-visual-assets/SKILL.md y plantillas; evidence/D03.md.

Las rutas son relativas a la raíz del repositorio. Los nombres nuevos son destinos propuestos que A02 fija antes de implementarlos. Pedir al integrador una reasignación si aparece una necesidad fuera de esta lista; continuar con lo independiente.

## Lista de tareas

- [ ] Separar tres rutas: ilustración con herramienta de imágenes GPT, esquema exacto con SVG/HTML y gráfico de datos con código reproducible. Definir cuándo corresponde cada una.
- [ ] Crear ficha de encargo: propósito, unidad, caso, objeto focal, relación visible, colores semánticos, composición, referencia de estilo y huecos para etiquetas.
- [ ] Prescribir inspección antes de editar imágenes de referencia y revisión visual/científica posterior. Para generación/edición usar la herramienta y skill imagegen disponibles; no fijar modelos/API o CLI obsoletos en la skill.
- [ ] Exigir texto alternativo, pie, procedencia, derechos, indicación conceptual/simulado/observado, dimensiones y peso. Mantener números, ecuaciones y etiquetas exactas en código cuando sea necesario.
- [ ] Ensayar una ficha usando una figura existente y señalar errores que obligan a repetirla: escalas engañosas, objetos inconsistentes, etiquetas falsas o color como única señal.

## Criterios de aceptación

- [ ] D03-AC1: La skill decide el medio de producción por necesidad pedagógica y exactitud.
- [ ] D03-AC2: Incluye una lista verificable de inspección y un manifiesto de salida por asset.
- [ ] D03-AC3: Una imagen GPT nunca se presenta como observación o resultado científico real.
- [ ] D03-AC4: Un agente conoce qué revisar y cómo devolver un recurso que falla sin aceptarlo por su apariencia.

## Evidencia y validación

Skill y ficha de ensayo, revisión de un recurso existente con criterios aplicados. Esta tarea no exige generar una imagen nueva.

Aplicar los gates proporcionales de VALIDATION.md. Completar [el informe de entrega](../templates/DELIVERY.md); marcar un criterio solo con evidencia. El agente propone entrega; el revisor acepta la tarea en BOARD.md.

## Criterio de logro

Los encargos visuales pueden ejecutarse y revisarse con un lenguaje visual coherente.

## Límites de esta tarea

No producir una estética diferente por sesión ni incrustar texto técnico no comprobado.
