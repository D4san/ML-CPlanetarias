## Lista de tareas

- [ ] Especificar una acción Ver ejemplo por unidad explicativa, no por párrafo. La acción abre la ficha del caso o navega a ella y ofrece acceso explícito a la fuente externa.
- [ ] Mostrar pregunta, observación/representación, resultado o uso, interpretación y límite; incorporar imagen solo cuando aporte y tenga alt/procedencia.
- [ ] Para enlaces externos, indicar destino y comportamiento; conservar navegación accesible y no abrir nuevas pestañas sin señalizarlo.
- [ ] Implementar las mismas referencias en presentación, lectura y tarjetas directas/interactivas. La política de rutas oculta ejemplos de rutas deshabilitadas; un ejemplo compartido se conserva si lo usa una ruta habilitada.
- [ ] Probar recurso ausente, enlace mal formado y fuente pendiente en el flujo editorial; el sitio publicable no ofrece botones vacíos. Documentar fallback HTML sin JavaScript.

## Criterios de aceptación

- [ ] C03-AC1: La acción funciona con teclado y toque y tiene un destino real identificado por ID.
- [ ] C03-AC2: Cada ficha permite distinguir qué ilustra el caso y qué respalda el recurso externo.
- [ ] C03-AC3: El mismo ejemplo puede aparecer en distintas vistas sin duplicar contenido y respeta disponibilidad de rutas.
- [ ] C03-AC4: La validación impide publicar unidades explicativas con un botón sin destino válido.

## Evidencia y validación

Tests de resolución de IDs/rutas, interacción y fallback; axe y móvil del panel o página.

Aplicar los gates proporcionales de VALIDATION.md. Completar [el informe de entrega](../templates/DELIVERY.md); marcar un criterio solo con evidencia. El agente propone entrega; el revisor acepta la tarea en BOARD.md.

## Criterio de logro

Todo autor de una unidad puede añadir un ejemplo mediante referencia, sin implementar una interacción propia.

## Límites de esta tarea

No incrustar páginas de terceros ni añadir tracking; no convertir cada párrafo en un botón redundante.
