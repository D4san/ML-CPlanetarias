## Disponibilidad actual y migración

- `src/pages/sistema/index.astro` monta S01 directamente y contiene el fallback HTML; el alias
  `src/pages/sistema/s01/index.astro` redirige a `/sistema/` conservando el hash.
- `config/course.config.ts` selecciona las tres rutas de S01, pero aún no controla una lista
  común de sesiones ni elimina páginas/alias del build. B03/B04 implementan esa diferencia.
- Ningún paquete de `inbox/` entra en `src/content.config.ts`; las colecciones aprobadas siguen
  siendo `docs/content/sessions`, `docs/content/concepts` y `docs/content/exercises`.
- Cuando una sesión quede excluida, B04/G03 deben retirar página, alias, índices, backlinks y
  enlaces profundos del build; un asset público solo se filtra si el generador lo determina por
  referencias. La configuración no es un control de acceso.
- Los conceptos independientes podrán permanecer si están aprobados y no enlazan a sesiones
  excluidas. Los ejercicios dependientes exclusivamente de una sesión excluida no se ofrecen.

## Criterios de aceptación

- A03-AC1: cumplido. ADR-0002 distingue procedencia Obsidian con `source_note` y procedencia
  repo con `source_path` relativo real; no se crea una nota ficticia.
- A03-AC2: cumplido. La tabla incluye origen, estado, derechos/condición editorial, destino y
  promoción pendiente para cada paquete y artefacto relevante.
- A03-AC3: cumplido. El trabajo técnico puede usar el piloto/fixtures sin alterar `status`,
  `visibility` o `publish_ready`; la promoción exige una representación pública revisada.
- A03-AC4: cumplido. Se separan páginas, alias, índices, backlinks, rutas profundas y assets,
  con la condición de que B04/G03 implementen y prueben la exclusión real.
