# Evidencia E06 · Evidencia y límites

Estado propuesto: aceptada.  
Responsable/revisor: Codex integrador. Fecha: 2026-09-08.  
Dependencias usadas: E01, B02 y B03.

## Resultado

`EvidenceScene` separa `apertura`, `capacidad` y `afirmacion`, con hashes `#evidencia`,
`#evidencia/capacidad` y `#evidencia/afirmacion`. La gráfica compara subajuste, ajuste útil,
sobreajuste y datos no vistos; el desafío final limita la afirmación a condiciones, comparación y
partición.

## Aceptación

| Criterio | Resultado | Evidencia concreta |
| --- | --- | --- |
| E06-AC1 | aprobado | IDs `s01-evidence-opening`, `s01-evidence-capacity`, `s01-evidence-claim` coinciden con inventario, `s01Parts` y ficha específica. |
| E06-AC2 | aprobado | Capacidad y afirmación son estados propios de interacción; estación, parte, ruta e historial permanecen en el contenedor. |
| E06-AC3 | aprobado | Las tres partes pasan 1920×1080 y 390×844; la tarjeta directa extensa conserva scroll y no se confunde con evidencia científica. |
| E06-AC4 | aprobado | SVG con título/desc, controles de capacidad, fieldset de afirmaciones, feedback aria-live, axe y movimiento reducido pasan. |
| E06-AC5 | aprobado | El inventario conserva la cadena baseline → no vistos → interpretación y la cautela contra mecanismo/universalidad. |

Criterio de logro: cumplido para la escena. Los números y resultados externos siguen sujetos a
fuente y proceso en F01/F04.

## Defectos y límites

- La gráfica es conceptual y no presenta valores de desempeño inventados.
- Una buena predicción no se eleva a mecanismo físico ni validez universal; F01/F04 deben conservar
  el alcance de cada fuente.
