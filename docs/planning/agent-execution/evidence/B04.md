# Evidencia B04 · Disponibilidad, páginas e identidad

Estado propuesto: aceptada.  
Responsable/revisor: Codex integrador. Fecha: 2026-09-08.  
Dependencias usadas: B03, A03 y los validadores de contenido B01.

## Resultado

`course-availability.ts` es el resolvedor común para sesiones, rutas y paths. Home, índices,
backlinks, layout, cabecera y pie consultan la configuración. La ruta dinámica de sistema genera
solo el root y el alias legacy de S01 cuando la sesión está disponible; al excluirla no quedan
archivos estáticos de `/sistema/` ni `/sistema/s01/`.

build bajo root; el build con `BASE_PATH=/preview` deja el montaje del prefijo a la infraestructura
de hosting y conserva los enlaces relativos mediante `withBase`.

## Defectos y límites

- La vista previa local no monta físicamente un reverse proxy en `/preview`; por eso la comprobación
  de subruta se basa en el build con `BASE_PATH` y en los href/src generados. El servidor de hosting
  debe montar ese artefacto bajo el prefijo configurado.
- S00 no tiene página de contenido todavía; su disponibilidad contractual no implica que exista una
  sesión visible.

## Entrega al siguiente agente

Usar `getAvailableSessionIds`, `isSessionAvailable`, `isRouteAvailable` y `getSessionPath`. El
perfil real de `config/course.config.ts` queda en S01 y no hay servicios temporales activos.
